#+TITLE: Dotfiles

This repository contains the configuration files and custom automation scripts
for my Omarchy (Arch Linux) environment. It serves as a live backup and a sync
point for eventually migrating this configuration to a desktop setup.

* Configurations

Quality-of-life enhancements, keybindings, and theming for my core workflow
tools:

- *Terminal & Multiplexer:* Alacritty, Tmux
- *Editor & Viewer:* Neovim, Doom Emacs, Sioyek
  - Org notes, PDF templates, and spelling corrections in Neovim:
    [[file:nvim/ORG-WRITING.md][Org writing guide]]
- *Wayland & UI:* Hyprland Lua configuration, Omarchy's Quickshell UI,
  Hyprlock, and Hypridle
- *Writing:* Org mode with Typst math, plus clean LaTeX PDF export for
  write-ups and essays (see [[file:doom/README.md][doom/README.md]])

The Omarchy runtime supplies the rice engine, menus, hardware panels, OSD,
notifications, and polkit UI. This repository supplies the authoritative
personal configuration. Omarchy's preinstalled applications, system
provisioners, theme packs, screensaver, background switcher, and branded lock
screen are not enabled.

* Vim-style desktop navigation

Caps Lock acts as Super. These bindings work alongside the original arrow
shortcuts, with classic =dwindle= tiling remaining the default.

| Shortcut | Action |
|----------+--------|
| Super + H/J/K/L | Focus left/down/up/right |
| Super + Shift + H/J/K/L | Swap window left/down/up/right |
| Super + backslash | Toggle current workspace between dwindle and scrolling |
| Super + Alt + J | Toggle split orientation (dwindle) |
| Super + F1 | Show desktop keybindings |
| Super + Alt + K | Show tmux keybindings (unchanged) |

Hold Super+H/J/K/L (or Super+arrows) to keep navigating, Super+Return to
spawn multiple terminals, or Super+W to close successive focused windows.
The existing 600 ms keyboard repeat delay is retained. Navigation is capped
at roughly 8 steps/second, terminal launch and close at roughly 3/second,
without slowing ordinary typing. Releasing the key stops repetition and
resets the cooldown for deliberate quick taps. Close uses the normal app
close request, not force-kill, but holding it can still close unsaved work
in apps without confirmation. Swap shortcuts are still single-action.

Inner and outer gaps are zero, with the original 1-pixel theme-colored
borders retained. New scrolling columns default to half the viewport width.
Existing manually sized
columns retain their sizes until resized or recreated.

To practice, switch to workspace 9 with Super+9, press Super+backslash, and
open a few windows. Use H/L with Super to navigate horizontally. Press
Super+backslash again to return to classic tiling. The toggle remembers each
workspace's layout under =~/.local/state/omarchy/workspace-layouts/= across
reloads and logins. Switching back may rearrange the previous split tree.
This is Hyprland's scrolling layout, not a separate Niri session.

** Scrolling-position bar indicator

The local =luciano.scroll-position= Quickshell plugin sits after the workspace
buttons. It is only visible on scrolling workspaces and shows the focused
tiled window's position, for example =2/5=, with clickable markers:

- Filled circle: focused window.
- Hollow circle: fully in the viewport.
- Half circle: partially in the viewport.
- Dim dot: off-screen.
- Hover a marker for its window title, click it to focus that window.

The count is *windows, not columns*. Floating windows and hidden group tabs are
excluded. A floating window with focus produces =–/N= rather than claiming that
a tiled window is focused. The strip is bounded to 12 markers around the
focused window, with chevrons when more lie outside the shown range. Geometry
is read left-to-right, then top-to-bottom for stacks, matching this setup's
horizontal scrolling layout. It is not a pixel-accurate scrollbar or an
occlusion detector: visible means intersecting the monitor viewport.

The widget follows the workspace on its own monitor, responds to compositor
events, and uses a 1.5-second fallback refresh for pans/layout changes that do
not emit an event (5 seconds while hidden). Each query runs one =hyprctl=
process, with no shell or =jq= pipeline. Marker objects persist through title
and viewport updates so hover and clicks remain stable. All source lives in
=omarchy/plugins/luciano.scroll-position/= and is deployed by the existing
=omarchy= config symlink, without patching Omarchy itself.

Diagnostics and regression checks:
#+BEGIN_SRC sh
omarchy-shell luciano.scroll-position status
node --test omarchy/plugins/luciano.scroll-position/model.test.cjs
#+END_SRC

After editing plugin code, =omarchy-shell shell rescanPlugins= refreshes
discovery. If the QML engine retains an older component, use
=omarchy-restart-shell=. To remove the indicator, remove its entry from
=omarchy/shell.json= and run =omarchy-shell shell reloadConfig=.

Validated on 2026-10-18: eleven model tests, actual bar-marker click, directional
focus and swap actions, floating exclusion/retiling, dwindle hide/scrolling
show, window closure/count updates, and fresh shell startup. Multi-monitor
and rotated/scaled-screen calculations have fixture tests, not physical
multi-monitor validation. Synthetic keyboard injection did not trigger the
global shortcuts, so live navigation tests invoked their configured
dispatchers directly. All disposable test windows were closed afterwards.

* Provisioning a new machine

=./provision= takes a fresh Arch install to this environment end to end:
packages first, then the symlink layout. It is idempotent, so running it on an
existing machine only fills in what is missing.

#+BEGIN_SRC sh
git clone https://github.com/dlmuschamp/dotfiles ~/dotfiles
cd ~/dotfiles && ./provision --hardware --services
#+END_SRC

| Flag | Effect |
|------+--------|
| =--hardware= | Also install =packages/native-hardware.txt= (AMD laptop specific) |
| =--no-aur= | Skip =yay= and every AUR package |
| =--services= | Enable SDDM, NetworkManager, Bluetooth and ufw |
| =--yes= | Do not pause for confirmation |

Package sets are plain newline-delimited manifests under =packages/=:
=native.txt= for portable official-repo packages, =native-hardware.txt= for
kernel, firmware and GPU packages that should be reviewed on different hardware,
and =aur.txt= for AUR packages. =yay= is absent from =aur.txt= because provision
builds it from source first. Regenerate the candidate lists with =pacman -Qqen=
and =pacman -Qqem=.

Provision ends by printing the few steps that still need a human, notably the
SDDM/PAM installers and the Zen profile setup below.

* Deployment

To deploy configuration only, without touching packages, run the bootstrap from
any checkout location:

#+BEGIN_SRC sh
./bootstrap
#+END_SRC

It pins the user-space Omarchy runtime under =~/.local/share/omarchy=, then
symlinks the tracked configurations into =~/.config=, personal commands into
=~/.local/bin=, and the tracked font files into =~/.local/share/fonts=.
Existing non-symlinked targets are moved to timestamped backups rather than
overwritten.

After bootstrap (or whenever the greeter drifts), install the tracked SDDM
theme and login PAM policy (needs sudo / fingerprint once):

#+BEGIN_SRC sh
dotfiles-pam-login
dotfiles-sddm-install
#+END_SRC

Hyprlock and the desktop both read
=~/.local/state/omarchy/current/background=. The SDDM greeter copies that
same image into its theme as =background.jpg=.

Required packages are tracked in =packages/= and installed by =./provision=.

** Notifications

Desktop notifications are rendered by *omarchy-shell* (Quickshell), not mako or
dunst. =graphical-session.target= pulls in =mako.service= even when it is
disabled, and mako usually wins the race for =org.freedesktop.Notifications= at
login. When that happens, popups appear to work but omarchy-shell never
registers as the notification server --- so dismiss/invoke shortcuts and
screenshot edit toasts silently fail.

=./bootstrap= masks and stops =mako.service= so omarchy-shell can own the dbus
name. =mako= is also omitted from =packages/native.txt= for the same reason.

Keybindings (from =hypr/bindings.lua=):

| Shortcut | Action |
|----------+--------|
| =Super + ,= | Dismiss last notification |
| =Super + Shift + ,= | Dismiss all notifications |
| =Super + Ctrl + ,= | Toggle do not disturb |
| =Super + Alt + ,= | Invoke last notification (e.g. open screenshot in Tensaku) |
| =Super + Shift + Alt + ,= | Notification history |

After a screenshot (=Print=), the toast includes a click action and the
=Super + Alt + ,= shortcut both run =tensaku-edit= on the saved file.

*If notifications misbehave after an upgrade or login*, check who owns the
dbus name and restart the shell:

#+BEGIN_SRC sh
busctl --user list | grep Notifications   # should show quickshell, not mako
systemctl --user is-enabled mako          # should be masked
./bootstrap                                 # re-apply the mako mask
pkill -f 'quickshell.*omarchy'              # autostart relaunches omarchy-shell
#+END_SRC

** Keyboard remaps (=keyd/=)

=keyd/default.conf= applies kernel-level remaps (Hyprland and TTY):

| Key | Effect |
|-----+--------|
| Yoga Copilot | Ctrl (firmware chord =LeftShift + LeftMeta + F23=) |
| Physical Win | Hold: nav layer --- =h/j/k/l= → arrows |
| Caps Lock | Super via =caps:super= in =hypr/input.lua= (not keyd) |

Window focus/move stays on Omarchy's =Super + arrows=. With Caps as Super
and Win as the nav layer, =Caps + Win + hjkl= is the home-row form of
=Super + arrows=. =Win + hjkl= alone emits bare arrows.

#+BEGIN_SRC sh
dotfiles-keyd-install    # install keyd, copy config to /etc/keyd, enable service
sudo keyd monitor        # press Copilot / Win+hjkl to confirm
#+END_SRC

Do not drop =f23= from the Copilot chord unless =keyd monitor= proves the
hardware omits it --- a two-key =Shift+Meta= remap would also eat real
=Super + Shift + letter= binds.

GTK apps follow dark mode via the tracked =gtk-3.0/= and =gtk-4.0/=
=settings.ini= overrides (=prefer-dark= + =Adwaita-dark=). Bootstrap clones
[[https://github.com/ubuntu/yaru][ubuntu/yaru]] into =~/.local/src/ubuntu-yaru=
and installs the Yaru icon flavors Omarchy themes reference (including
=Yaru-magenta=) under =~/.local/share/icons=.

The bar, menus, and panels draw their icons from Nerd Font private-use
codepoints, and =fontconfig/fonts.conf= points the =monospace= alias at
=JetBrainsMono Nerd Font= so those glyphs resolve. =fonts/omarchy.ttf= supplies
the menu glyph.

Log out and back in after the first deployment so UWSM loads the tracked
environment.

* Zen (=zen/=)

Zen stores prefs inside a profile directory whose name is randomized per
install, so =bootstrap= resolves the active profile from =profiles.ini= and
links =zen/user.js= into it. Launch Zen once on a new machine to create the
profile, then re-run =./bootstrap=.

=user.js= carries only the SSO workaround described below. Bookmarks, saved
passwords and extensions are account data and are deliberately not stored in
this repo; pull them down with Zen Sync instead.

** The Microsoft SSO logout loop
Historical experiments: [[file:zen/outlook-sso-findings.txt]]. Earlier claims of a
single confirmed root cause were not conclusive across repeated regressions.

*** Targeted repair (2026-10-19)

The scripts incorrectly wrote =trackingprotection=2= for ETP exceptions.
Firefox's ETP allow-list requires =1=. The cold-start =zen= wrapper now applies
an idempotent, backed-up ETP-only correction before starting the browser. It
does not clear cookies, site storage, service workers, extension settings, or
restored tabs. A running browser is left alone, with a profile lock protecting
the repair against concurrent startup.

#+BEGIN_SRC sh
zen-sso-fix --repair-etp # Zen must be fully closed, ETP exceptions only
zen-sso-guard           # read-only, same as --check, safe while Zen runs
zen-outlook --check     # read-only metadata and permission diagnostics
zen-outlook             # open outlook.cloud.microsoft/mail/ via zen wrapper
#+END_SRC

The guard no longer treats missing localStorage token-like keys as proof of
corruption. MSAL can use sessionStorage or memory. It never deletes site data
or rewrites extension databases. Temporary diagnostic snapshots use a private
unique directory and are removed on exit.

=bootstrap= links =zen/zen.desktop= into =~/.local/share/applications/= so the
app menu uses the wrapper. After repair, verify login, a second mail tab,
browser restart, reboot, and access the following day. The logout root cause
is not proven resolved until these real-world checks pass.

*** Explicit recovery only

#+BEGIN_SRC sh
zen-outlook --recover   # closes Zen, deep wipe + harden + reopen, costs Duo
zen-sso-fix --deep      # deep wipe only, including session-restore files
zen-sso-harden          # legacy extension hardening, Zen must be closed
#+END_SRC

These commands are not used during normal startup. Deep recovery clears broad
Microsoft/Stanford/Duo authentication state and moves browser session-restore
files. Prefer the targeted ETP repair first. If failures persist, compare a
clean dedicated Zen profile without extensions or custom preferences before
another broad reset. Existing global privacy relaxations in =zen/user.js=
were not changed by this targeted repair.

* Maintenance (=bin/dotfiles-update=)

#+BEGIN_SRC sh
dotfiles-update            # interactive full upgrade: repos, AUR, cache, Doom
dotfiles-update --check    # unprivileged check, notify only, changes nothing
#+END_SRC

A weekly user timer (=systemd/user/dotfiles-update.timer=, Sundays at 11:00)
runs =--check= and sends a desktop notification with the pending update counts.
It deliberately does not upgrade unattended: Arch upgrades occasionally need a
human for a manual intervention posted to Arch news, a =.pacnew= merge, or a
kernel bump that wants a reboot, and an interrupted =pacman -Syu= leaves the
system half-upgraded. The check is unprivileged because =checkupdates= and
=yay -Qua= both work against a throwaway copy of the pacman database, so no
=sudoers= exception is needed.

The upgrade path also runs =doom sync=, since Emacs packages pin to the Emacs
version and a bumped =emacs-wayland= otherwise leaves Doom throwing
native-compilation errors.

* Custom Automations (=automations/=)

The automation stack is actively being refactored to use *event-driven hardware
interrupts* rather than resource-heavy polling daemons.

- *Bluetooth Audio Daemon (=epoll_manager=):* A custom Linux-native C daemon
  utilizing =epoll= that listens to BlueZ D-Bus signals. Upon connection or
  disconnection of specific headsets (like the Moondrop Edge or Aria), it safely
  forks a Bash script to seamlessly route Pipewire audio sinks, apply
  device-specific parametric EQs via EasyEffects, and dispatch Spotify to a
  designated Hyprland workspace.
- *Legacy Polling (=hardwareListener.sh=):* Shell scripts managing power
  profiles based on battery percentage and toggling a "tablet" mode (currently
  being migrated to the event-driven architecture).

* Typst Workflow (=bin/typst=)

A custom shell wrapper that streamlines typesetting. Running
=typst [document_name]= automatically scaffolds the file from a core template
(=typst/templates/write_up.typ=) and spins up side-by-side instances of Neovim
and Sioyek for live-preview editing.
